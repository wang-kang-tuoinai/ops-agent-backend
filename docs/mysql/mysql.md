# 为什么使用B+树而不是B树
1. 因为B+内部节点只索引不存储具体信息,数据库信息全部存储在叶子节点,所以说一个盘块所存放的索引数量更多,可以减少IO次数
2. B+树的查询效率更稳定,因为B+树总是从根节点到叶子节点才返回,所以查询效率更稳定
3. B+树非常有利于范围查询,因为B+树叶子节点通过双向链表串联起来,所以他范围遍历非常方便

# 聚簇索引与二级索引
聚簇索引即主键索引, 每一张表必须都有一个聚簇索引,如果你没有指定primary key 那么mysql会自己选择你指定的非空且唯一的key当作主键索引,如果没有非空且唯一的,mysql会默认帮你创建一个隐藏索引。 你可以为表中的其他列创建二级索引, 那么mysql会为这个索引单独创建一个B+树, 内部节点存储的是你指定的二级索引 ,叶子节点存储的是二级索引加上对应的聚簇索引, 如果你在select中要查询的信息全部包含在二级索引里面那么就直接返回给你,如果没有,那么他会拿着叶子结点的主键信息回表查询.

# 联合索引
联合索引就是把表中多个列组合在一起当成一个索引，非常适合多个条件的范围查询，比如某某省大于40岁的男生
比如创建联合索引(a,b,c)就是先按a排序，a相同再按b排序，b相同再按c排序。最左前缀原则就是当你想要利用联合索引，你的查询条件里必须包含最左边的元素，当时从左向右匹配，先看你的查询条件里有没有a，没有就走全表扫描，再看你有没有b最后看你有没有c。
比如查a，c那么只有a能起作用。如果是b，c那么只能全表扫描
