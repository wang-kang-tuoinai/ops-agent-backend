# 1. 缓存穿透

定义：缓存穿透就是请求数据库本来就不存在的数据
危害：当大量请求来请求不存在的数据的时候，每一次请求都会直接落到数据库，由于数据库处理速度较慢，数据库可能会宕机。
原因：1.恶意的攻击，比如大规模发送不存在的请求。
       2.代码的逻辑有问题
解决办法：1. 缓存空数据，当发现数据库没有储存这条数据的时候，缓存一个·空数据，设置较短的超时时间，缺点：当大量请求都是请求不同的不存在的对象的时候，那么将起不到任何缓冲作用，所有请求还是直接打向数据库，并且还会在redis里面缓存大量空对象，占用内存。
2.布隆过滤器，虽然可能存在误判情况(比如明明不存在，却判断他存在)
但是他的内存占用率很低，并且能够隔绝绝大部分无效请求。很适合大量恶意请求请求不存在的key的情况

# 2. 缓存雪崩
定义：当缓存宕机的时候，或者大量key突然集体失效的时候，所有请求会集体打向数据库，数据库会承受不了这样的压力导致崩溃。
解决办法：搭建redis集群，提高可用性。给每一个key的过期时间加上一个随机的抖动，数据库层面加上限流，熔断。

# 3. 缓存击穿
定义：某一热点数据失效导致一瞬间针对这一热点数据大量请求涌向数据库，可能会导致多次请求数据库多次更新缓存。
解决办法：1. 加上互斥锁，保证一次只有一个请求去查数据库，并更新缓存，后面所有的请求都走缓存。2.只给key设置逻辑过期时间，逻辑过期时间过了，再由一个单独的线程去更新，代码逻辑比较复杂，并且可能存在逻辑不一致的情况。
