# RDB
Redis默认启用的就是RDB，他的流程是当执行BGSAVE命令的时候，主进程会fork出一个子进程专门用来处理IO备份的，可以在不阻塞主进程的前提下完成备份，并且RDB是二进制文件内存占用比AOF小，且恢复速度快，但是RDB备份频率没有AOF这么高，可能会丢失数据。
流程：主进程fork出子进程 -> 采用写时复制的做法不阻塞主进程，并且确保备份的就是那一时间点的数据 -> 当备份完成后会用新的rdb文件覆盖旧的。

# AOF
AOF会将每次执行成功的写命令转换成RESP格式追加到内存中的AOF缓冲区，然后Redis会在每次事件循环结束的时候，根据配置的策略决定命令以何种方式写入文件并同步到磁盘，一般建议每秒一次fsync刷回磁盘，这是一种权衡性能以及安全的折中方案。

为了避免AOF文件无限扩大，Redis有ReWrite机制 他会直接遍历内存里的数据逆向生成能够见当前数据的最小指令集，相比RDB，他的指令恢复速度较慢，并且AOF占文件空间也较大。
