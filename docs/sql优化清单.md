## 建立表的时候
- [ ] 主键是否时递增的？(防止B+树频繁的分裂以及重排)
- [ ] 字段类型是否做到了极简？
- [ ] 字段是否定义为NOT NULL并赋予了默认值？
- [ ] 时间字段用不用？
- [ ] 单表字段数以及单行大小是否失控？

## 写SQL时候
- [ ] where条件上的列是否有索引？
- [ ] 是否避免了对索引列进行了运算或者是调用了函数？ 
- [ ] LIKE是否是右模糊('user%')而不是左模糊？
- [ ] SELECT是否是只查询自己需要的列？
- [ ] 是否发生了隐式类型转换？(比如phone字段时varchar类型,但是你却写where 13800000000 这样不加引号 mysql会把字段转化为整形在比对 导致索引失效)
- [ ] 分页是否是深分页？
- [ ] JOIN被驱动表的关联字段有没有建立索引？
- [ ] OR的连接的条件是否都有索引？
- [ ] 是否用limit限制了结果集的大小？
## 建立索引时
- [ ] 联合索引的顺序是否符合最左前缀原则？
- [ ] 是否避免了对区分度低的列(比如性别)也建立了索引？
- [ ] 是否利用了索引覆盖？
- [ ] 长字符串是否使用了前缀索引(Index(col_name(20)))?
- [ ] 是否存在“冗余索引”？(比如有联合索引(A,B)就不用在为A单独建立索引)
## 排查慢查询的时候
- [ ] 跑过Explain了吗，type是什么？
- [ ] rows预估值和实际数据量差距大吗？
- [ ] Extra字段预警了吗？
- [ ] 优化器选错索引了吗？
- [ ] 是被查询拖慢的,还是锁拖慢的？
- [ ] 是否一条SQL语句被高频率调用？
